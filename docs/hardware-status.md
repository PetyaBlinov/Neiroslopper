# Плата и аппаратный статус

На 01.11.2026 программный перенос и физическая наладка имеют разный статус.

| Проверено | Ещё предстоит |
| --- | --- |
| На MKS DLC32 v2.2 установлена официальная FluidNC v4.1.1 Wi-Fi | Перенести исполнительные устройства с Arduino |
| Новый sender прочитал версию, YAML и состояние реальной платы | Подтвердить разъёмы, драйверы, микрошаги и направления |
| Диагностика прошла в Idle без исполнительных команд | Подготовить и загрузить рабочий YAML |
| На плате обнаружена Default/Test Drive без I/O | Отдельно проверить реле и выполнить короткий физический рисунок |

Работающая механика пока остаётся на Arduino+GRBL. Подключение новой платы по USB не означает завершённый перенос станка.

## Связь с пультом

- USB: выберите фактический COM-порт; используется115200 бод.
- Wi-Fi: укажите `tcp://IP-платы:23`. Для собственной сети FluidNC обычно используется `tcp://192.168.0.1:23`.
- Браузерный интерфейс FluidNC доступен по HTTP. Его адрес не является TCP-адресом поля подключения в пульте.
- USB не обязателен для передачи команд по Wi-Fi. Плата при этом продолжает нуждаться во внешнем питании.
- На проверенной плате для включения потребовались внешние12В. Установленная сборка использует Wi-Fi; Bluetooth не включён.

Первичное подключение приложения читает данные. Оно не отправляет движение, включение реле, снятие Alarm или запись YAML.

## Двигатели и реле

Текущая логика — XY и соленоидный подъём ручки. Соленоиду не нужен драйвер шагового двигателя Z. Если портал использует два двигателя, дополнительный мотор может занять физический канал Z как второй X; это нужно отразить в конфигурации и проводке.

На старом CNC Shield клон X и физический выход Z на MKS — разные аппаратные решения. Сопоставляйте их по назначению, а не по совпадению расположения разъёмов. Логика ESP32 —3,3В; пригодность входа прежнего релейного модуля для такого сигнала пока не подтверждена.

Управление ручкой использует coolant/flood_pin из фактического YAML. Пин GPIO4 и схема через NPN из прежнего архива не считаются уже установленными на этой плате. Силовая цепь катушки12В остаётся отдельной от сигнального GPIO.

## Проект YAML

Мастер экспортирует config.draft.yaml из введённых параметров. Он не загружает его на плату. Диапазоны параметров и ключи сверены с исходниками FluidNC v4.1.1.

Разводка I2S в мастере взята из документации семейства DLC32 с примером v2.1. Она требует отдельной сверки для имеющейся v2.2. Шаги/мм, максимальная подача, ускорение и ходы вводятся по реальному устройству; архивные значения не заменяют измерение.

Текущий экспорт рассчитан на явно выбранный вариант без концевиков. Если концевики уже установлены, их конфигурацию нужно подготовить отдельно, а не отключать ради шаблона.

## Потеря связи

Пульт не повторяет движения и не возобновляет задание автоматически. При доступной связи СТОП отправляет программный reset.

В официальной FluidNC нет отдельного JD heartbeat/reset на8888 и таймера реле из старой Uno-прошивки. Если Wi-Fi уже оборвался, команды и состояние выхода, принятые ранее, могут сохраняться. Программная кнопка не заменяет физическое отключение питания приводов. Допустимый режим катушки, нагрев и механика проверяются на установке.

## Следующий аппаратный этап

1. Зафиксировать фактическое число двигателей, драйверы и разъёмы MKS.
2. Подтвердить уровни и полярность входа реле.
3. Подготовить конкретный YAML под эту проводку.
4. Загрузить выбранную конфигурацию и проверить направления короткими перемещениями.
5. Отдельно проверить подъём ручки, задать два угла и выполнить небольшой рисунок.
