# Native DWIN / JD-DGUS 2.1

Neiroslopper 0.9.0 поддерживает компьютерную сторону протокола из [PR №2 товарища](https://github.com/PetyaBlinov/Neiroslopper/pull/2), commit `0174a3abd3945288dad330e52b8f468cf58c13b1`. Это подготовка к совместимой паре прошивок MKS и дисплея. В этой работе устройства не перепрошивались; физическая совместимость и работа нового меню не проверены.

## Что меняется

| Действие | Кто выполняет |
| --- | --- |
| Стрелки, шаг, скорость, два угла, STOP на Native-панели | MKS с совместимой прошивкой |
| Подготовка рисунка и потоковое рисование | Программа на ПК и FluidNC |
| Вопрос с RU/EN-клавиатуры, до120 символов | ПК готовит короткий ответ, экран показывает до112 символов |
| Голос с панели | Микрофон ПК; запись и расшифровка требуют проверки в окне ПК перед отправкой |
| Обновить лист | ПК передаёт снимок420×278, до160 сегментов; это не видео |
| Просьба запустить рисунок с экрана | Появляется кнопка подтверждения в пульте; затем обычное подтверждение движения |

Экранный помощник отвечает на вопросы. Если ответ предлагает изменить рисунок, правку выполняют и проверяют в окне помощника на ПК. Ответ панели сам не применяет геометрию и не запускает станок. Локальное ручное управление MKS не означает автономного рисования без компьютера.

В Native-окне разрешения на вопросы помощнику и использование микрофона ПК по умолчанию выключены и включаются отдельно. Открытие окна не начинает запись или запрос.

## Подключение и согласование

Обычные USB/Wi-Fi-подключения штатной FluidNC и прежний JD-DGUS1-мост сохранены. Native выбирается по версии протокола в ответе платы; один маркер не подтверждает проводку или готовность.

Для управления с ПК Native использует Wi-Fi: основной канал TCP23 и отдельный канал панели TCP8888 того же подтверждённого числового IP MKS. Сначала проверяется фактический канонический YAML с ожидаемыми осями и реле. Для действия ПК получает временное исключительное право управления; локальный экран и поток ПК не должны одновременно двигать оси. При изменении поколения листа, перезапуске, потере подтверждения или несовпадении адресов действие останавливается и автоматически не повторяется.

Углы Native хранятся на MKS и передаются в пульт. Снимок не измеряет движение моторов. Простой просмотр состояния и пассивное отключение ПК не должны сбрасывать чужое локальное управление. Явный STOP остаётся отдельным действием.

Открытие настроек DWIN не подключает устройство. После явного подключения основной MKS с Native-протоколом приложение может открыть связанный канал панели на том же проверенном IP. Для USB-сеанса Native движение с ПК не разрешается без сетевого согласования; это не ограничение обычной штатной FluidNC.

## Совместимые внешние материалы

Ссылки, размеры и SHA-256 собраны в [машиночитаемом списке](dwin-compatible-manifest.json). Бинарники в эту поставку пульта не копируются и автоматически не загружаются.

- [Сборка MKS и соответствующие исходники](https://github.com/levsasha2018-crypto/Neiroslopper/tree/0174a3abd3945288dad330e52b8f468cf58c13b1/dwin-assistant/firmware): FluidNC v4.1.1 + JD-DGUS2.1, заявлена MKS DLC32V2.2. В исходном README `.bin` указан как приложение для0x10000 при соответствующей схеме разделов; это не полный образ платы и не универсальная инструкция записи. Пример YAML нельзя подменять действующим без сверки разводки.
- [Интерфейс DWIN800×480](https://github.com/levsasha2018-crypto/Neiroslopper/tree/0174a3abd3945288dad330e52b8f468cf58c13b1/dwin-assistant/display): пакет страниц и кириллический шрифт с отдельной лицензией DejaVu.

Исходные отчёты обоих пакетов отмечают `hardware_tested: false`. Точная модель установленного DWIN, схема разделов MKS, UART, активный YAML и текущая прошивка требуют отдельной проверки перед возможным обновлением. Программа0.9.0 их не меняет. Подготовка отменённой Bluetooth-прошивки не возобновлялась.

## Проверки кода

Автотесты используют подставные состояния MKS, протокольные пакеты и ответы помощника. Проверяются старый мост, версия/поля Native, владение управлением, смена поколения листа, разрыв, STOP, ограничение предпросмотра и отсутствие применения рисунка из ответа панели. Настоящие UART, COM, экран, микрофон и прошивка в этих тестах не используются.
