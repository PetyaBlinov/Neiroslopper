# Что проверено

Neiroslopper **0.4.0**, 08.11.2026: **220 автоматических тестов прошли**. Используются имитаторы, окна Tk и TCP только на localhost; порт физического станка тесты не открывают.

## Проверка 0.4.0

Полный набор: 220 тестов OK. Проверки Bluetooth используют выдуманные описания COM-портов и не вызывают ни сопряжения, ни открытия реального порта. Проверяются отсутствие автоматического подключения, исключение USB/входящих портов, выбор нескольких/неопределённых кандидатов, исчезновение устройства и блокировки во время работы. Одиннадцать DPI-тестов используют подставные Windows API и скрытые Tk-окна, проверяют порядок/fallback, отсутствие двойного масштабирования и сохранение символьных размеров/наследования стиля. Регрессия контролирует отсутствие повторных configure при неизменном состоянии.

В отдельном офлайн-процессе реально включён PMv2, получен масштаб 2.0 (экран 2880×1800). При окне 2200×1400 в Bluetooth-режиме кнопки углов, запуска, подключения и обновления помещаются, предпросмотр 1360×355; очереди команд пусты, подъём по умолчанию включён. Внешний вид просмотрен в Windows. Это проверка интерфейса, не соединения с платой.

Ограничение: масштабирование по начальному DPI; полная динамическая перестройка старой Tk 8.6 при переносе между разными мониторами не заявляется. BT1 не записан, физический Bluetooth/DWIN ещё не испытан.

## Проверка оформления 0.3.0

Пять новых регрессий проверяют разделение левого тестового меню и правого рабочего процесса, отсутствие строки этапов, скрытый журнал без побочных действий, повторное открытие справки с Esc и видимость основных действий при минимальном размере для USB/Wi-Fi/Демо. ## Автоматические проверки

При первой проверке GitHub на Python3.11 обнаружилось освобождение объектов Tk в фоновом потоке после закрытия окна. Убрана неиспользуемая ссылка контроллера на интерфейс, добавлено ограниченное ожидание завершения worker перед уничтожением Tk и очистка тестовых окон в основном потоке. Новый тест проверяет порядок завершения; полный локальный набор после правки — 194 теста.

| Группа | Содержание |
| --- | --- |
| Сеанс | Идентификация FluidNC, канонический YAML, no-I/O-диагностика, готовность |
| Моторы | G21/G91, преобразование осей, одна команда на ручной ход, ранний Idle до старта Jog, ожидаемая конечная точка |
| Подъём | Полярность, M8/M9, выключение после остановки, срок 10 с для MKS и прежний 1,65 с для Uno |
| Ошибки | Повреждённые координаты, неполная запись, отсутствие повторов, STOP, гонки и перезапуск ESP32 |
| Wi-Fi | Поиск и проверка FluidNC, отмена, поздние результаты, выбор из нескольких плат и сохранённые подсказки; без настоящей LAN |
| Транспорт | USB без перенастройки DTR/RTS во время движения, фрагменты TCP, EOF, частичная отправка и тайм-аут |
| Окно | USB/Wi-Fi/Демо, один job на нажатие, блокировка занятых элементов, обновление кнопок до диалога ошибки |
| Редактор и Демо | SVG, кириллица, история, офлайн-эскиз, два угла; MKS в Демо использует режим 10 с |
| YAML | Числа, макросы запуска, STEP/DIR, два мотора портала, конфликтующие GPIO и концевики |

Для MKS проверен ход 10 мм при 80 шагах/мм, F150 и ускорении 10: расчётное движение около 4,25 с выполняется одной командой. Проверены переходы подряд без обязательного охлаждения 2,2 с, цельный G1, отказ слишком длинного хода до M8 и отсутствие продления срока повторным M8.

Запуск на Windows с Python3.11–3.14 и Tkinter:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

## Настоящая установка

По USB считаны **v4.1.1-JD-DGUS1**, конфигурация, Idle и сеть FluidNC/AP 192.168.0.1/Telnet 23. Обнаружен DWIN-мост UART 23/33. Реле и подъём проверялись физическими импульсами M8/M9. После восстановления провода пользователь подтвердил работу соленоида.

05.11 загружен `neiroslopper_portal_fixed.yaml`. Сохранена резервная копия; после перезапуска прочитаны выбранный файл и полный YAML. Подтверждены изменение только второго портального DIR на `i2so.4:low`, сохранение JD/DWIN, реле и остальных параметров, состояние Idle. Движений при загрузке не было.

## Пределы результата

Физическое движение после инверсии Z ещё не проверено. Не подтверждены калибровка 80 шагов/мм, токи, ход 1000 мм, длительный режим катушки, настоящее Wi-Fi-подключение и рисунок на MKS. Расчётные координаты не измеряют вращение моторов.

Причина первого ALARM:3 не объявлена полностью установленной: прежний журнал содержал Abort Cycle до сброса приложения. Наблюдение встречной работы моторов объясняет инверсию Z, но не доказывает единую причину всех прежних USB-ошибок.

Реальные журналы, абсолютные пути компьютера, пароли и резервные копии прошивки остаются локально. Исходный пульт команды сохраняется отдельно без правок; версия 0.3.0 включает рабочую адаптацию, обновлённое оформление и тесты.
