# Neiroslopper — пульт для MKS DLC32 v2.2 и FluidNC

Запуск на этом ноутбуке: **Neiroslopper.lnk** (ярлык с логотипом проекта) или **START.cmd**. Откроется отдельное окно Windows. Программа начинает с DEMO, сама не подключается к станку и не включает выходы.

Это рабочая адаптация кода из соседней папки «Код приложения/PROGRAM». Исходная папка товарища оставлена без изменений. Используется уже установленная официальная FluidNC v4.1.1; Arduino-скетч на ESP32 не переносится, команды движения выполняет сама FluidNC.

## Что работает

- USB (115200) и Wi-Fi/TCP штатной FluidNC. Для Wi-Fi введите в поле подключения `tcp://192.168.0.1:23` либо актуальный локальный адрес платы. Не путайте этот адрес с HTTP-панелью в браузере.
- Подключение для просмотра версии, координат и YAML, в том числе при штатной Default/Test Drive без физических выходов. Пульт не требует чужого DWIN-моста на порту 8888.
- Ручные перемещения, ориентация осей, два угла бумаги, скорость, тестовый квадрат, СТОП/ESC.
- SVG, предпросмотр, ручной редактор, русский и латинский текст, фигуры, проекты, отмена/повтор и прежние примеры.
- Соленоид через штатные M8/M9: M8 включает катушку, M9 выключает. В нынешней механике питание ПОДНИМАЕТ ручку. Электрическая полярность определяется фактическим `coolant/flood_pin` и проверяется отдельно от направления механизма.
- Кнопка «Настроить плату…» создаёт проект YAML из введённых параметров. Экспорт ничего не загружает на плату. Настоящие GPIO реле, шаги/мм и ходы заранее не подставлены.

На старте доступен эскиз A4 210×297 мм: SVG и редактор работают без оборудования. Эскиз не является физической калибровкой станка.

## Первый запуск

1. Откройте START.cmd. Для проверки выберите DEMO и нажмите «Подключить». Движения в этом режиме виртуальные.
2. Для настоящей MKS выберите профиль MKS DLC32 v2.2 / FluidNC и нужный COM либо адрес TCP. Штатное питание платы 12 В необходимо; один USB вашу плату не питает. Первичное подключение читает данные, без reset, разблокировки, движения и включения реле.
3. Если плата отвечает Default/Test Drive, это ожидаемо для выполненной ранее прошивки. Программа показывает причину неготовности и оставляет доступными редактор и мастер конфигурации. Движения и тест реле недоступны до рабочего YAML.
4. Перед подготовкой YAML сопоставьте текущие моторы и реле с MKS. Мастер предусматривает XY и необязательный второй мотор X через физический разъём Z. Он не превращает соленоид в шаговую ось Z. Шаблон разводки относится к семейству DLC32; ревизию v2.2 нужно отдельно сверить.
5. После настройки настоящей платы нажмите «Проверить конфигурацию FluidNC». В настройках ручки задайте проверенные HIGH/LOW и направление подъёма. Непрерывное питание по умолчанию выключено, полярность заранее не подтверждена.
6. Проверьте направления коротким шагом. Подведите ручку в верхний левый угол, сохраните его; затем сохраните нижний правый. После этого можно запускать рисунок из предпросмотра.

## Что ещё требуется на реальной установке

Пользователь сообщил, что исполнительные устройства к MKS пока не подключены и хочет перенести их по аналогии с Arduino. После подключения самой платы к ноутбуку новый код успешно прочитал её на COM5: официальная FluidNC, Idle, Default (Test Drive no I/O). Рабочий YAML, GPIO реле, микрошаги, шаги/мм, направления, ходы и проводка не подтверждены. Поэтому реальный рисунок на MKS этим переносом ещё не испытан. Это приложение, а не завершённая аппаратная наладка.

Логика Arduino сохранена, но проводка не переносится контакт-в-контакт. ESP32 использует 3,3 В, старый вход реле мог управляться от 5 В. В схеме с двумя моторами портала третий драйвер MKS может использоваться как второй X, а не как независимый Z; выбор зависит от реальной проводки. Силовая цепь соленоида остаётся отдельной цепью 12 В через контакты реле.

В отличие от специальной прошивки из архива товарища, штатная FluidNC не содержит его DWIN/lease-сервиса и аппаратного таймера Uno для соленоида. Пульт прекращает отправку и пытается выполнить сброс при ошибке, не повторяет движения и не продолжает задание автоматически. При потере Wi-Fi уже принятые команды могут продолжать выполняться; программный СТОП не является аппаратным выключателем. Настройка катушки не заменяет проверку её нагрева и допустимого режима.

## Дополнительные возможности

Камера, сканер и обводка растров сохранены как дополнительные модули. Для них установите зависимости через INSTALL_CAMERA.cmd. Их работа на реальной камере в этой адаптации не проверялась. DWIN остаётся дополнительным старым интерфейсом; встроенный сетевой мост из специальной прошивки отсутствует в штатной FluidNC. ИИ, голосовые модели и облачные помощники не добавлены.

## Установка на другом компьютере

Нужен Windows Python 3.11–3.14 x64 с Tkinter. Выполните INSTALL.cmd, затем START.cmd. Базовые зависимости находятся в vendor/wheels и устанавливаются без интернета. Локальную .venv переносить на другой компьютер не нужно; создайте её установщиком заново.

Настройки этой копии лежат в data; подтверждения реле и калибровка из исходной программы сюда не перенесены. Диагностика ошибок — data/serial-diagnostics. launch.py сохраняет ошибки запуска вместо незаметного закрытия окна.

## Проверки и источники

Все 70 тестов прошли; 45 Python-файлов проверены компиляцией. Сверены SHA-256 всех 64 исходных файлов товарища: изменений нет. Новый sender дополнительно проверен на настоящей плате COM5 только чтением $I, $Config/Dump и ?. Тесты находятся в tests, результаты — в VERIFICATION. Проверяются настоящий протокол через имитатор, ошибки связи, СТОП, полярность, отсутствие движения при диагностике, TCP через localhost, DEMO, редактор и генерация YAML. Они не заменяют прогон физического плоттера.
